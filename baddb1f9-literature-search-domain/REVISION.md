# 修订说明（v1 → v2）

上一版得分区间 59–75（均值 66.9），五维均未拿满。本次修订**逐条对着评分维度改**，不做泛化润色。

## 1. 实际效果（40 分）：补「计数闭合」与「可核验」的硬机制

**问题**：v1 只在 SKILL 里要求「留理由码与依据片段」，但没有可执行的校验，扣分点在结果正确性与可核验性。
**改动**：新增 `scripts/search_tool.py audit`，强制 `原始→去重后→已判定` 三段闭合，并校验三条正确性规则：判定合计必须等于去重后条数；理由码必须在字典内；**理由码族别必须与判定方向一致**（用纳入码却判 exclude 直接报错）。不通过返回非零，SKILL 明确写「不得交差」。
**理由**：该维考察「理由码是否指向真实片段、去重是否误并或漏并、各环节条目数是否闭合」——把这三件事从"要求"变成"跑不过就交不了"。

## 2. 使用增益（25 分）：从「声称有效」改为「可算的一致率 + 公平对照」

**问题**：v1 没有任何双人标注与一致率概念，质量增益无从证明；这是 25 分里最大的一块空缺。
**改动**：新增双人独立标注协议（A/B 互不可见）、`agreement` 命令计算决策一致率与 **Cohen's κ**（含 include 子集上的理由码一致率）、门槛「一致率≥0.80 且 κ≥0.60 未达标不得进下一环节」；`result.json` 增 `gain` 字段，要求同题录、同标准版本各跑一次基础 Agent 与 Skill Agent，报准确率/κ/人工核对条数。
**理由**：该维原文要求「提升纳排准确率与双人一致率」「通过公平对照证明」——κ 与对照表是唯一能落地的证据形式。

## 3. 创新增益（15 分）：把三个创新点做成可验证的机制

**问题**：v1 的流程与通用 Agent 差别不大，创新证据缺失。
**改动**：①**协议版本化 + 回溯重判**：协议带版本号，标准变更必须记 change_log 并说明影响哪些已判记录；②**理由码体系**：独立字典文件，含边界情形约定（仅摘要/预印本/亚组/多报道/语言不符）；③**分歧自动分类**：仲裁表把分歧分为 decision / reason_code / evidence 三类而非只记"有分歧"；④**审计链**：审计日志逐行 input_n/output_n 可首尾相接。
**理由**：该维点名「标准版本管理与回溯重判、理由码体系、分歧自动分类、审计链生成」正是这四个点。

## 4. 可靠体验（10 分）：异常改成逐类给动作

**问题**：v1 只有一句「无结果/冲突/缺元数据如实说明」，异常处理这一项最多拿零头。
**改动**：新增 7 行异常处置表——DOI 缺失、摘要为空、编码乱码、导出格式不一致、标准版本冲突、两位标注者僵持、库超时限流，每行给**具体动作**（如「先按 UTF-8/GBK 重解一次，仍乱码则标字段不可用，不臆造」）。
**理由**：该维明确考察「对 DOI 缺失、摘要为空、编码乱码、导出格式不一致、标准版本冲突、僵持的识别与处置能力」。

## 5. 生态贡献（10 分）：把口头流程做成五套可复用模板

**问题**：v1 只有 SKILL.md 与一个脚本，模板/字典/表格式全缺，可复用性为零。
**改动**：新增 `templates/protocol.md`（协议+纳排判据+增益对照+边界）、`templates/reason_codes.md`（理由码字典+边界约定）、`templates/worksheets.md`（标注表/仲裁表/审计日志/覆盖率表四张 CSV 列定义与示例行）。
**理由**：该维直接考察「协议模板、标准表、理由码字典、配置、示例、适用边界是否齐全」「检索式模板、去重脚本、标注表、仲裁表与审计日志格式能否被复用」。

## 6. 去重：区分「精确重复」与「近似候选」

**改动**：`dedup` 同时输出精确合并组与**近似候选组**（同年 + 标题 Jaccard≥0.55），近似只列候选不自动合并。
**理由**：该维批评「去重靠标题肉眼比对，同一研究的预印本与正式版被当两条、或两条不同研究被误合并」。近似候选 + 人工裁决正好卡在这两个错误中间。

## 本次未改动的部分

- 不预置任何案例答案；`bench/fixtures` 明确标注为**自测夹具与调用示例**，不冒充正式案例结果。
