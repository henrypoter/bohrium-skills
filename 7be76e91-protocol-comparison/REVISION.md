# 修订说明（v2 → v3，比较与选择）

## 实际效果（40）
- 从偏“单方案生成”的 v2 收敛到本题核心：新增 `compare`，强制保留全部候选及独立版本，以相同七类实验字段加成本、周期、风险、证据和硬约束横向比较。
- 成本拆为一次性/机时/耗材/人工/返工，时间拆为准备/执行/排队/表征/返工，使用有限数与分项和校验，不再只检查字符串非空。
- 硬约束 `fail/unknown` 均不可选；每个未选项须有具体理由，选择有证据，敏感性写结论翻转阈值。
- 新增 `input_id/comparison_schema_version/source_version`、候选版本、结构化来源定位、工具运行命令和版本化变更记录，强化独立复核。

## 使用增益（25）
命令一次列出缺失字段、算术错误、不可行原因和选择逻辑错误，减少人工对齐与逐项重算。尚未在官方三案例做基础 Agent 公平对照，质量/效率数值保持未知，bench 不冒充实测增益。

## 创新增益（15）
- `feasibility --spec` 将设备可用性/档期、耗材库存/货期、预算、时间窗、有限参数域放在同一资源合同中检查。
- 参数交集为空、币种/单位不一致和缺合同均明确拦截；可行性与主观评分分离，避免低成本“抵消”硬不可行。
- 全候选不可行时输出 blocked 恢复路径，而非硬选相对最好。

## 可靠体验（10）
异常表覆盖设备不可得、排期满、耗材缺货/超预算、参数窗口冲突、时间窗冲突、输入缺失、内容不确定和候选全部不可行。全不可行必须有 `selected_candidate_id=null`、逐候选舍弃理由、`all_candidates_infeasible` 和 `recovery.action/decision_owner`。

## 生态贡献（10）
更新 `SKILL.md`、比较矩阵/风险异常模板、接口示例与使用说明；所有命令纯标准库，无外部数据文件依赖。

## 相对基础 Agent 的边界与证据
基础 Agent 也能写出方案叙述，本 Skill 的新增边界是**可重复执行的结构/算术/硬约束/异常闸**，不是宣称自动证明科学真伪、真实排期或采购价格。本地回归 `python3 bench/bench_run.py` 为 **44/44**，每个新命令均有正向与变异用例。距榜首仍缺官方固定案例的实际科学内容表现、三次重复稳定性与公平质量/效率轨迹。
