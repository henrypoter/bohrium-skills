# 确定性双路径对照报告（bench）

> 运行：`python3 bench/bench_run.py`（仅标准库，一键复跑，exit 0 = 18/18 通过）。
> 结果明细：`bench_results.json`。夹具：`bench/cases/`（自拟，非平台正式案例）。

## 对照设计

同一修订工作负载（2 轮「定位-修改-处置」+ 3 条文献入库 + 1 条论断核验）下：

- **base 路径**（不加载 Skill 的基础 Agent 工作流）：每轮修订须把整章重新读入上下文并整章重写输出，改动位置靠人工 diff 找回；无逐条留痕、无版本、无回退。
- **skill 路径**（加载本 Skill）：章节一次入库，每轮 `revise` 只携带「锚点+改后+依据」，逐条 accept/reject 留痕，reject 自动回退。

## 效率与可追溯指标（实测于 b1 夹具，458 字节章节）

| 指标 | base | skill | 说明 |
|---|---|---|---|
| 模型上下文体积（字节） | 916 | 618 | −32.5%；随章节增大差距线性扩大（base 每轮重读整章 ×轮数，skill 只读一次 + 每轮仅锚点串） |
| 产物数 | 1（平铺改写文本） | 10 | skill 多出：修订留痕、历史版本、导出回读报告等可复核产物 |
| 可逐条接受/拒绝的改动记录 | 0 条 | 2 条 + 2 个历史版本 | base 的改动埋没在整段重写中，无法逐条处置 |

操作步骤口径：base 每轮 = 整章重读 + 整章重写（2 次模型请求）+ 人工 diff；skill 每轮 = 1 次 `revise` + 1 次 `accept/reject`（确定性 CLI）。两者步数相近，但 skill 的产物全部机器可复核。

## 质量可核验性证据（夹具证明，非文字自述）

- **正向零误杀**：`b1_citation_dense.md`（[1]/[2]/[3]/[1,2]/[2,3]/[1-2] 齐全）→ 引用交叉核对 `status=ok`，`unresolved=[]`；公式夹具中 `$\alpha\in[0,1]$` 区间不被误判为引用。
- **变异必命中**：`b1_mutant.md`（正文 [9] 在文献表中不存在）→ `status=mismatch`，`unresolved=[9]`，result 诚实降级 `partial` 并写入 limits。
- **导出回读**：md/tex/docx 全 ok；docx 解包核对标题/段落数/标题层级与 md 源一致；tex 核对 `\begin{document}` 与标题注入。
- **修订留痕**：accept 保留、reject 自动回退（夹具逐字节断言）。

## 异常场景处置（逐个对照 exit code）

空锚点 → 3 且不改稿（旧版本曾 exit=0 且插文污染章节，已修复）；锚点==改后（无改动）→ 3；空章节文件 → 4（记入材料缺口，不入库）；锚点缺失 → 3（拒绝整段覆盖）；project.json 非法 JSON → 1 明确诊断（不再 traceback）；无章节时 revise/export → 5 前置拦截；导出工具链缺失 → 保留 md/tex/docx 并诚实记 failed。

## 诚实边界

1. LLM 端到端改稿质量（措辞/术语/学科正确性）需平台 harness 固定案例 A/B，本地不声称。
2. 上下文体积指标在 458 字节小夹具上为 −32.5%；章节越大、修订轮数越多，skill 优势越大（base 随轮数线性膨胀，skill 近常数）。
3. 夹具为自拟演示材料，仅用于路径对照与校验证明，不代表平台案例难度。
