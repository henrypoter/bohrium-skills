# 定位与能力边界（positioning）

本文回答创新增益评分点的核心问题：本 Skill 相对基础 Agent 与现有编辑方案**新增了什么、改进了什么、边界在哪里**。所有能力均可由 `bench/bench_run.py` 一键复现（18 项断言，exit 0）。

## 能力矩阵

| 能力 | 基础 Agent（裸 LLM 改写） | pandoc / python-docx 路线 | 本 Skill |
|---|---|---|---|
| 修改落在指定位置（句子/段落级） | 整段重写，位置靠人工找回 | 不涉及（格式转换工具） | 原文锚点精确替换；锚点缺失退出码 3 拒绝改稿，**从机制上禁止整段覆盖** |
| 逐条接受/拒绝 + 回退 | 无（一次性输出） | 无 | proposed→accepted/rejected 状态机；reject 自动回退原文并留历史版本 |
| 改动依据与来源留痕 | _prompt 里有，产物里没有_ | 无 | 每条修订含 before/after/reason/source/版本进出版 |
| 论断-证据绑定核验 | 无（模型自述来源不可信） | 无 | `claim` 证据必须在来源文件**逐字回查**到，否则 needs-human 进入 confirmations_needed |
| 引用-文献表一致性 | 无 | 无 | 正文 `[n]/[n,m]/[n-m]` 与文献表交叉核对；悬缺引用标 mismatch 并使 result 降级 partial；公式内区间不误判 |
| 导出后可编辑 + 结构自洽 | 纯文本 | 可编辑但无回读自检 | md/tex/docx 三通道 + **回读自检**（解包 docx 核对标题/段落/层级，核对 tex 骨架），结果入 export_report |
| 版本谱系与断点续作 | 多个无法对应来源的副本 | 无 | history/ 版本谱系 + project.json phase 状态机 + 原子写盘 |
| 依赖 | 无 | 需安装 pandoc / python-docx | 纯 Python 标准库（docx 为内置 OOXML 写入器） |

## 方法层面的实质改进

1. **修订锚定**：把「改哪」从模型的自由发挥约束为「必须在原文中逐字存在的锚点」，使修订粒度、位置可机器校验（anchor_count、exit 3），这是质量稳定性的根源。
2. **证据回查**：`verify` 不是信任模型填写的 source，而是重新打开文件逐字查找 evidence——把「可核验性」从承诺变成脚本行为。
3. **导出回读**：写入后重新解包/解析产物核对结构，而不是「没抛异常就算成功」——直接针对「格式塌了也不报」的真实失败模式。
4. **诚实降级状态机**：材料缺口、悬缺引用、未核验论断、导出失败分别记录并使 status 降级 partial，任何时刻都先落一份可复核的 result.json。

## 边界（不做什么，如实声明）

- 不做学科正确性判断：术语/结论是否正确依赖领域专家，Skill 只保证「改动可追溯、证据可回查」。
- 锚点为纯文本精确匹配：对重排后文本、跨行断句需人工选准锚点（建议公式行整行替换）；锚点缺失宁可拒绝也不猜测。
- docx 为基础样式（标题三级、列表、正文）；复杂样式以 tex 为准。markdown 表格原样保留为可编辑文本行，不转成 Word 原生表格。
- PDF 预览依赖环境预装 latex 工具链；缺失时诚实记 failed，不影响 md/tex/docx 交付。
- 引用核对覆盖数字编号引用（`[n]/[n,m]/[n-m]`）；作者-年份制（如 (Smith, 2020)）不做编号重排。
