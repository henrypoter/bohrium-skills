# 相对现有方案的边界与价值（创新点定位）

本文件回答评分点「是否证明创新点相对已有方案的边界和价值」，逐项给出**已有方案能做什么 /
不能稳定做什么**，以及本 Skill 的明确边界。

## 1. 能力矩阵

| 能力 | 基础 Agent 直写 | 通用写作工具/语法检查 | 静态申请书模板 | **本 Skill** |
|-|-|-|-|
| 从散乱材料抽取证据并编号台账 | 不稳定，易遗漏或混淆来源 | 不支持 | 不支持 | **支持**：任意嵌套 case.json 遍历 → S#/P# 台账（文献/领域/申请人前期基础三类） |
| 论断级引文覆盖强制 | 靠自觉，无回检 | 不检查引用-论断对应 | 不支持 | **支持**：含数字/「表明/显示/证明」的论断行未挂 [S#]/[P#] 即 FAIL |
| 不可核验修饰拦截 | 常自发写出「国际领先」 | 通用拼写检查不覆盖 | 不拦截 | **支持**：禁用词表 + 「填补[国内/重大]空白」变体正则 |
| 缺口↔研究内容双向映射 | 无此概念，缺口与内容常脱节 | 不支持 | 不支持 | **支持**：孤儿缺口/孤儿内容/引用未定义缺口三向检出（评审人视角自检） |
| 前期基础防虚构 | 易编造申请人成果 | 不支持 | 不支持 | **支持**：前期论断必须挂清单内 [P#] 或标【待补充】，越界即报「疑似虚构」 |
| 引用编号可核实 | 引用编号无清单约束 | 不支持 | 不支持 | **支持**：[S#]/[P#] 越界（引用无法核实）即 FAIL |
| 目标-内容-路线-指标对齐 + 路线图 | 数量常不一致（目标三个路线两条） | 不支持 | 仅给空槽 | **支持**：条目数对齐核查 + matrix.csv 自动生成 Mermaid 路线图 |
| 段落-要素-证据三级对应 | 无留痕 | 不支持 | 不支持 | **支持**：pack 自动回填 source_mapping.used_in |
| 诚实降级（材料缺失/解析失败/超长） | 常硬写或崩溃 | 不适用 | 不适用 | **支持**：partial + material_gaps/conflicts/uncertainty，不虚构 |

## 2. 三个核心创新点及其边界

**（1）缺口↔研究内容双向映射（评审人视角自检）。**
立项依据段尾把缺口编号 `缺口G#`，研究内容逐条注明 `回应缺口Gx`，check 双向检出三类脱节：
有缺口无内容承接（孤儿缺口）、有内容未回应缺口（孤儿内容）、内容引用不存在的缺口（未定义）。
这对应评审最常见的「立项依据与方案两张皮」质疑。
边界：依赖作者按约定写 `缺口G#`/`回应缺口Gx` 标号；只做标号级对应，不判断内容是否**真的**能回答缺口（属科学判断）。

**（2）前期基础 [P#] 真实清单绑定。**
init 把证据拆为文献/领域材料 [S#] 与申请人前期基础 [P#] 两类清单；check 校验：引用编号越界
（清单外编号 = 疑似虚构或无法核实）＋ 研究基础章节含「前期/本课题组/申请人已/已发表/已制备」
的论断必须挂 [P#] 或标【待补充】。
边界：类别判定基于 JSON 路径关键词与文献特征正则，材料组织方式特殊时可能误分类，此时台账
可由人工修正后再 check（check 不依赖分类，只依赖编号清单）。

**（3）机械核对全下沉为 0 模型请求脚本。**
证据抽取、引文覆盖、要素对齐、双向映射、映射回填、路线图生成全部为确定性脚本
（init/check/pack），模型只做研读与写作。机械核对环节 18 次手工动作 → 3 次 CLI，
核对上下文降 85.1%（`bench/bench_report.md` 第 3 节，可复跑）。
边界：该对照只度量机械核对环节开销，不度量 LLM 端到端写作质量（归平台白板对照）。

## 3. 与「基础 Agent」的差异证据

`bench/bench_run.py` 以 1 个正例 + 10 个变异夹具证明校验器「正向零误杀、变异必命中」，
并以 6 个异常/稳定性场景（解析失败、指南不明、超长输入、幂等、重复运行、打包回填）
证明降级与一致性行为；全部为确定性路径对照，可一键复跑，exit 0。

## 4. 不做什么（明确边界，避免过度声称）

- 不做引文语义核验：只核验「论断挂了台账内编号」，不核验「引文真的支撑该论断」（人工清单兜底）。
- 不做科学价值判断：不判断研究方案本身的创新性与可行性对错，只核验一致性与可追溯性。
- 不做模板版本化/多资助方适配：本题 3 个固定案例已由组织方限定七要素＋计划一致性约束，无此维度。
- 不生成引用条目：离线环境不联网补文献元数据，避免编造 BibTeX。
- 不替代专家：所有【待补充】与 conflicts 必须人工确认后才可提交。
