# 修订说明（v2，采集—迁移—恢复硬约束）

保留原有 DAG/断点续跑方案，新增采集迁移闭环、三类重点异常机检和真实产物哈希。bench 全为合成数据，不是官方案例答案或平台对照分数。

## 实际效果 40：从来源原文到事务目标的闭环

- `migration_check` 校验 collection 的真实来源定位、完整原文件、attribution、获取时间、记录数、SHA-256；来源记录数总和必须等于 integrity.source_count。
- 字段映射必须含 source/transform/on_missing，目标字段重复即拦截；unmapped 必须有原因和动作。
- 去重区分精确、合并、疑似、不同文献，决策需双记录引用和证据；疑似/同名不同文献不得自动删除。
- 记录恒等式为 `source = target + exact + merged + skipped - added`，去重计数与决策一致，附件差值逐项落清单，非预期差异不得 pass。
- `manifest`/`verify_manifest` 重算真实文件大小和 SHA-256，避免仅自报摘要。

## 使用增益 25：避免返工但不能虚报增益

状态驱动的 `resume` 保留已完成采集和映射，仅运行依赖已满足的后续步骤；现在 skipped 不再被误当 done，blocked/skipped 进入人工接管集。映射、去重、计数和附件一次机检减少逐行事后核对。没有平台公平对照时 gain 保持 null。

## 创新增益 15：可回滚事务 + 决策账本 + 恢复类型系统

相对基础 Agent 常见的“重试几次/重新跑一遍”，本版增加：①每批写入计数闭合、事务 ID、checkpoint 和 rollback_ref；②去重决策与删除数双向核对；③登录/下载/写入专项证据；④附件预期差异与缺陷分账；⑤来源和产物的可重算哈希。工具不判断论文内容质量，不证明实际网页语义，只拒收无法复核的交付结构。

## 可靠体验 10：自评三项缺口变成命令

`recovery_check` 正向同时覆盖登录态失效、下载失败、写入报错：

- 登录/二次认证必须停止转人工，且明确不记录凭据；自动重试绕过会失败。
- 下载必须记录期望/实际 Content-Type 等、部分文件保留状态；恢复后无完整性验证会失败。
- 写入必须有事务/批次和 attempted=accepted+rejected，回滚必须有引用。
- 另覆盖字段缺失、权限不足、元素缺失、超时、限流和同步冲突双版本。
