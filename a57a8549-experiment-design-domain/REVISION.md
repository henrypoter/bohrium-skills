# 修订说明（v2 → v3）

本轮将“领域总课题”从一张静态路由表改为**带证据定位的分诊器 + 五条可执行流程 + 动态结果机检**。只改本目录；无共享核心修改、无第三方依赖、无正式案例答案或虚构平台得分。

## 1. 实际效果（40）

- `route --task --case --out`：对 generation/comparison/feasibility/parameter/interpretation 做逐行强信号匹配，输出 task/case SHA-256、行号或 JSON Pointer、逐字 quote、workflow/命令/交付项；混合任务保留全部流程，无匹配明确 unsupported。
- 每条流程有实际算法而非只有 prose：`compare` 真算归一化排名、硬拒绝和权重敏感性；`resources` 真算四态资源、样本、成本与排期；`optimize/replay` 真跑有限域多目标成本搜索；`interpret` 真算最小二乘、R²、残差/MAD异常。
- `audit` 按当前路由动态要求专属产物和算术一致性，不再要求不相关字段，也不允许只完成 primary 就遗漏混合子任务。
- `verify` 扩展到路由判断、参数、响应和七类可行性证据，实际验源哈希和逐字定位；结果增加 schema/tool/plan/input/permissions 五类版本信息。

## 2. 使用增益（25）

`gain BASELINE SKILL --out` 强制相同 case/input/permissions，同路由口径计算所需交付段、专属输出、定位判断和路由异常覆盖；效率只使用双方真实 telemetry。没有基础 Agent 文件时必须 not_run，不能把 48 个合成 bench 当作使用增益。

## 3. 创新增益（15）与相对基础 Agent 的边界

- **可追溯分诊**：不只是关键词标签，还保留每次命中的原句和输入哈希，能审查“为何走该流程”。规则并不等价开放域语义理解；不明输入停止，不强行分类。
- **比较敏感性**：让方案选择可解释、可测权重脆弱性；仅处理同口径有限指标，不解决不可通约科学价值。
- **可行性算术+参数重放**：让资源“可行”与参数“最优”能复跑；复杂资源日历、连续/非线性优化仍在边界外。
- **残差异常绑定**：输出异常 ID 与独立重测动作，不直接编造异常原因；OLS+MAD 仅是描述性基线，不替代因果/混合效应分析。

## 4. 可靠体验（10）

共同异常表逐条覆盖题面不支持输入、工具异常、权限、数据缺失、执行失败，均含识别信号、具体动作、处置类型、负责人和绑定字段。按可行性/参数/解释路由自动追加缺页、设备不明、伦理未定、无可行解、指标矛盾等异常。bench 验证 unsupported 不默认生成、执行失败异常漏登记必失败。

## 5. 生态贡献（10）

- `SKILL.md`：完整分诊表、五流程、异常与公平对照。
- `templates/plan_spec.md`：路由记录和五类输出模板。
- `bench/fixtures`：合成 task/case、comparison、observations、problem、routing/optimization 等最小示例。
- `bench/bench_run.py`：共 **48 项**，最终 **48/48 PASS**；五个 route 均检查无额外路由，所有命令均有正向零误杀与变异必命中。
