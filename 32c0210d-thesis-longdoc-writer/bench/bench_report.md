# 公平对照基准报告（bench）

本报告由 `bench/bench_run.py` 生成，数据可复跑：`python3 bench/bench_run.py`（结果同时落
`bench/bench_results.json`，实测 `BENCH PASS` exit=0）。

## 对照设计

同一案例（`bench/cases/`，自拟 demo：c1_full 材料齐全 / c2_gap 材料含缺口），两条路径：

| 路径 | 做法 |
|-|-|
| **baseline**（无 Skill，逐章手写） | 每章写作都重读 task+全部材料全文+已写章节；术语/引用/编号/结论数字靠人工通读全稿核对 |
| **skill**（加载本 Skill） | `--init → --plan → 逐章注入式写满（min_words 篇幅下限）→ --assemble --render → consistency.py(advisory, 5 规则) → --finalize`；**5 条主路径命令**（baseline 侧 6 条人工环节，且无留痕） |

上下文体积按真实文件实算：skill 路径实跑 `--plan` 读 `plan.json` 的材料映射（每章只注入
本章大纲行 + 映射材料 head（每文件≤1500字） + 已完成章标题与结论摘要）；baseline 按
「每章重读全部材料 + 已写章节 + 收尾人工通读 2 遍」计。

## 实测结果

| 指标 | baseline | skill | 说明 |
|-|-|-|-|
| 需进入模型的上下文（字符，c1_full 全案例） | 13225 | **1660** | **降 87.4%**；逐章 172→492 字，随章数线性增长而非随全文 |
| 需进入模型的上下文（字符，c2_gap 含缺口） | 12625 | **1660** | **降 86.9%**；缺口章由骨架+`【缺口】`承载，不依赖全量材料 |
| 手工易错动作（重读材料/回翻定位/术语统一/引用核对/编号重排/结论核对） | 6 类 | **0** | 全部转为可复跑 CLI 与 advisory 机器检查（5 条规则，误杀低） |
| 一致性检查记录（机器可复核、带文件+行号） | 0（仅人工通读，无留痕） | **5 条核心规则 issue/warn** | `consistency.json` 落盘可复跑（`rule_count=5`） |
| 篇幅纪律（防草稿化） | 无约束，易只写提纲式短章 | **plan.json 每章 min_words + `--assemble` 打印 LENGTH/SHORT** | 未达标只提示不阻断；实测短章夹具 `SHORT` 命中且 exit=0 |
| 夹具质量证据 | 无 | **正向零误杀；变异 5/5 规则命中且 exit=0 不阻断** | 正向 `issue=warn=0`；变异覆盖 5 条规则（cite-missing / float-missing / float-number / term-abbr / number-unsourced）全部检出 |
| 结构化落盘产物（c1_full 实跑清点） | 1（整篇 md） | **11 件**：plan.json + 5×chapters + manuscript.md/.html/.docx/.pdf + result.json | `--assemble --render` 一条命令即产出 md 与三态预览；另随检产出 consistency.json；changes.jsonl 按需追加 |
| 重复运行确定性 | 依赖人工 | **同输入两次 `--plan` 逐字节一致（实测 true）** | 规划阶段零模型请求、纯确定性 |

## 三条可复核的结论

1. **效率**：5 章案例上下文从 13225 字降到 1660 字（-87.4%）；逐章注入只随章数线性增长
   （+80 字/章的前文摘要），数万字规模下避免「后写章节重读全文」。
2. **质量（可核验性）**：baseline 的一致性核对是人工通读、无留痕、不可复跑；skill 的
   每次检查产出 `consistency.json`（类型/级别/文件/行号/证据/建议），正向夹具证明零误杀、
   变异夹具证明 5 条规则必命中——机器检查替代「反复通读全文」，且规则刻意少、不拖瘦成稿。
3. **可靠性**：c2_gap 材料缺口场景下管线照常产出（缺口记 `【缺口】`+gaps，不编造）；
   渲染、超长材料、中断续写、短章只提示等异常夹具见 `scripts/selftest.py`（实测 PASS）。

## 边界（不夸大，诚实声明）

- 本对照度量**路径开销与可核验性**，**不**度量 LLM 端到端写作质量（文字优劣、论证强弱）；
  后者需平台 harness 跑固定案例，本报告不声称「写得更好」。
- baseline 的「上下文体积」是按无 Skill 时必须重读全文的保守下界模型估算；不同基础
  Agent 记忆策略可能略好，但不会改变「每章需携带全文」的量级。
- 样例为自拟 demo（非官方评测案例），用于路径对照与方法演示；bench 内的示意章节正文
  由脚本生成，仅服务路径开销与产物清点，**不是**任何正式案例的预制答案。
