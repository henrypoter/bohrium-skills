# 相对现有方案的边界与价值（创新点定位）

回答评分点「是否证明创新点相对已有方案的边界和价值」：先给能力矩阵，再给三个创新点
及其边界，最后声明不做什么。

## 1. 能力矩阵

| 能力 | 通用写作助手（LLM 直写） | 文献管理器（Zotero/EndNote 等） | 引用/元数据校验工具（DOI 核对类） | **本 Skill** |
|-|-|-|-|-|
| 生成连贯学术段落 | 支持 | 不支持 | 不支持 | 支持（综合起草步） |
| 论断切分为可判定单元 | 不稳定，无显式产物 | 不支持 | 不支持 | **支持**：一论断一谓词，C# 编号贯穿成稿与矩阵 |
| 论断-来源绑定到具体段落 | 通常只给文献级引用 | 管理条目但不判定支撑 | 只核对条目真伪/格式 | **支持**：full/partial scope + 必填 note（判定理由） |
| quote 回原文逐字锚定 | 无 | 无 | 无（只查元数据） | **支持**：E5 子串核验，编造 quote 必拒 |
| 数值逐字锚定（数字对不上必拒） | 无 | 无 | 无 | **支持**：E7，full 绑定 quote 须逐字覆盖论断数值 |
| 强度词-证据等级机器对齐 | 无 | 无 | 无 | **支持**：E9，强词须 A 级最强绑定，弱证据强结论必拒 |
| 「引用真实但不真支撑」拦截 | 靠模型自觉，不稳定 | 不判定 | 不判定（存在性≠支撑性） | **支持**：E10 supported 必须含 full 绑定，仅 partial 必拒 |
| 正文编号↔矩阵双向核对 | 无 | 无 | 只核对参考文献表编号 | **支持**：M1（兼容 [C#] 与 [C#:E#]），E12 编号冲突必拒 |
| 冲突证据并陈与四值判定 | 易隐藏冲突 | 不判定 | 不判定 | **支持**：conflicted ≥2 绑定且正文并陈 |
| 结果可独立重跑复核 | 一份成稿，无过程 | 批注私有 | 一次性报告 | **支持**：论断清单+证据库+矩阵+核验报告全部落盘可重跑 |

## 2. 三个创新点及其边界

**（1）论断-证据绑定矩阵 + 内容级机器核验（E7/E9/E10/M1/E12）。**
不只是「提示模型标注来源」，而是把充分性判定落成结构化 binding（scope+note）并由
脚本复核：数值须逐字见于 quote、强词须 A 级最强绑定、supported 须含 full、正文编号
与矩阵双向一致、编号冲突必拒。夹具证据：`tests/test_report.md`（正向零误杀、
11 个变异全部命中）。真实 bug 修复证据：v2 曾把「A 级+C 级混合绑定」误杀、
放过了编号冲突，v3 由夹具复现后修复。
边界：verdict/scope/note 的语义起点仍由 LLM 给出，脚本保证**一致性与可追溯性**，
不能证明「原文在科学上足以支撑该论断」——后者仍需专家判断。

**（2）证据强度分级与措辞对齐的写作纪律。**
A-D 四级（多篇一致/单篇良好/小样本或仅摘要/推测不足）配允许措辞表，相关性不写因果、
单篇小样本不写共识、C/D 必带限定语；E9 把该纪律变成机器可执行的拦截。
边界：分级是启发式口径，不替代领域评审；等级上限规则（仅摘要封顶 C 等）是保守默认。

**（3）诚实优先的预算化交付回路。**
先写 partial result.json 再增量改进；六类异常显式降级（仅摘要/冲突/不足/元数据缺失/
格式权限/撤稿与原文摘要矛盾），不静默通过；核验报告落盘供第三方重跑。
边界：内容判定质量依赖 LLM 遵循工作流；超长材料受单次响应 token 预算限制，
需分段落盘。

## 3. 与「基础 Agent」的差异证据

`bench/bench_run.py` 在同一自拟案例上做确定性路径对照：论断-证据绑定率 0 → 1.0、
数值锚定率 0.833 → 1.0、越界强度词 4 → 0、冲突并陈 否 → 是、人工返工项 9 → 0、
可复核产物 1 → 4+。口径与边界见 `bench/bench_report.md`；与真实基础 Agent 的
LLM 质量对照由平台 harness 提供，本文件不声称替代。

## 4. 不做什么（明确边界，避免过度声称）

- 不联网检索新材料：材料外文献一律不引入，元数据只抄材料、缺失填 null。
- 不做学科正确性判定：只核验「论断-证据」的可追溯性与强度对齐。
- 不做 OCR/图表解析：PDF 解析依赖运行时工具，失败显式降级并标注。
- 不替代文献管理器：不承担文献库管理、去重、同步职责，可并存使用。
