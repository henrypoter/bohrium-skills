# 修订说明（v2 → v3，生成与优化）

## 实际效果（40）
- 强化六要素硬闸：变量补 `measurement_method`，判断补 `source_locator`，风险从三件套扩为触发、后果、缓解、止损、替代路径五件套。
- 新增 `controls`：先由研究目标和混杂声明 `control_requirements`，再验证实际对照的类型、映射、目的与依据，避免只有空白组或机械套对照。
- 成本/时间由字符串提升为可重算分项；样本量、单批容量和批次做整数下界检查。
- 新增 `input_id/schema_version/source_version`、结构化来源、参数与判断定位、版本化变更原因、实际工具命令记录。

## 使用增益（25）
一个 `optimize` 命令同时列预算、时间窗、批次、设备、库存、货期和参数问题，并给最小批次、预算余量、裁剪域，减少多轮人工查漏。尚无官方三案例基础 Agent 公平对照，不声称已测得质量或时间提升。

## 创新增益（15）
- `optimize --spec` 输出设备量程交集；对案例明确给出的线性参数成本模型，再按 `(budget-fixed_other_cost)/cost_per_unit` 求预算上限，输出带来源的定位化裁剪域。
- 所有参数裁剪均标 `requires_confirmation`，工具不静默改文件、不把截断等同科学等效；没有成本模型时不编造。
- `controls` 将目标→混杂→所需类型→实际对照变成可机检链；风险必须有替代路径。

## 可靠体验（10）
异常表和机检覆盖无设备参数/预算/时间窗、时间窗与样本量冲突、试剂缺货/货期超窗、设备排期满、参数空交集及内容不确定。资源阻断还需 `exceptions` 中的 trigger/action/alternative_path/impact/decision_owner/status。

## 生态贡献（10）
同步 `SKILL.md`、目标反推对照/参数裁剪/异常模板、合成接口示例和使用说明；纯标准库，无在线查询或第三方包依赖。

## 相对基础 Agent 的边界与证据
基础 Agent 可生成貌似完整的流程，本 Skill 提供的是**可复跑的对照反推、资源/算术/参数优化与异常记录硬闸**。它不能证明真实实验有效、安全获批或线性成本模型适用。本地回归 `python3 bench/bench_run.py` 为 **48/48**，每个新命令均有正向与变异用例。距榜首仍缺官方固定案例科学内容质量、跨体系重复稳定性、真实使用效率与公平基础 Agent 轨迹。
