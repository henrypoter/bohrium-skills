## 2. 失败模式 → 规则映射（创新证据）

每条确定性规则对应一个已记录的基础 Agent 失败模式，且随包夹具可复现：

| 基础 Agent 失败模式 | 对应核查 | 夹具证据 |
|---|---|---|
| 转录错误：t 值与 p 对不上 | statcheck 重算 | bio_mutant：t(18)=3.21 配 p=0.2 → warn（重算≈0.0049） |
| spin：不显著写成"显著改善/获益" | claim fail（cited 仅不显著来源） | bio_mutant S5 句 → fail |
| 结果段夹解释与文献，两节不分 | purity + structure | bio_mutant"这表明…机制 [C1]" → 2 条 warn；合并标题 → structure warn |
| 引用不存在的图/漏引材料图 | fig_ref 双向 | bio_mutant 图 3 → fail；图 2 → warn |
| 数字无出处/心算新数 | number 溯源 | bio_mutant 55.5% → warn |
| 证据清单自相矛盾 | source_consistency | bio_mutant S7（significant=true, p=0.2）→ warn |
| 缺局限或泛泛而谈 | structure + discussion_block + 局限四维模板 | bio_mutant 缺局限 → 2 条 warn |
| 整数容差吞并相邻小数（工具自身 bug） | number 匹配按书写精度 + 最近候选 | v2 曾把 4.8 错配 n=5；v3 修复并由 bio_good 回归 |

## 3. 方法改进点

1. **证据清单先行**（步骤 0 sources.json）：所有正文数值只能从清单复制，清单一改全文可机检重核——把"写得像"变成"可逐条对账"。
2. **核查报告对接评分维度**：report.json 的 `by_score_dimension` 把 fail/warn 映射到任务完成度/结果正确性/完整性/可核验性，修复前后差值即质量增益的机器可读证据。
3. **确定性优先、LLM 自查不作兜底**：调研表明 LLM 验证器召回率低（约 21%），故作告警而非兜底；所有机检规则随包回归（bench_run.py）。
4. **降调语言白名单**：NEG 词表覆盖"未达显著/无法判断显著/因果性无法确定"等诚实写法，保证降调不被误判为过度宣称（degraded 夹具零误杀）。

## 4. 边界（不做什么）

- 不做图表像素级数字化（OCR/读图取数）；图读数不清时进 uncertainty，禁止猜数。
- statcheck 仅 t/z 近似重算；F/χ²、置信区间换算、多重比较校正不实现。
- 不判断领域结论本身对错（如机制是否合理），只判断表述强度与证据强度是否匹配。
- 不联网检索文献；引用缺失时降调为"亦有报道"并落 uncertainty，不编造文献。
- 数值核查是"正文↔清单"一致性，不复算原始数据到统计量的全过程。
