# 修订说明（v2 → v3：研究方法与统计审查）

## 对齐判对标准

v2 把原句子串核验和六类计数作为主体，但 SKILL 末尾仍错偏“学术规范与合规”；零 issue 还容易与“未检查”混淆。v3 将主任务纠正为**设计—变量定义—统计方法—样本量—结果报告**五面，保留六类审查交叉矩阵，并把每条定位、严重度和可重跑交付变成 `gate` 硬约束。

## 实际效果（40）

- `coverage`：五个 facet、六个 category 都要求 checked/not_applicable/pending/unchecked 与实际 notes/reason；修复“没有问题就是没查”的语义漏洞。
- `statcheck`：对结构化提取记录检查双侧 p-CI 方向、z-p 复算、自由度、样本流守恒；特殊检验明确留人工复核，不以规则替代方法判断。
- `gate`：每条 issue 必须有 section + 细粒度定位、连续 quote、quote SHA-256、带来源内容 SHA-256 的 evidence、defect_type/review_status；校验 pass/issues/partial/failed 状态一致性。
- 分开 `fact_error/evidence_gap/norm_issue/suggestion`，建议级意见只能 minor，阻止把未报告当事实错误、把所有问题升格 critical。

## 使用增益（25）和可验证性

预检一次生成文本内容哈希、缺页/乱码/混排/图表/统计输出状态，减少人工反复判断“哪些能审”。原句、定位和统计复算错误由命令直接列出，减少回查与返工。正式 `gain` 只接受同输入、同工具权限、同预算的真实对照；没有对照填 null，不把本 bench 的规则覆盖率冒充平台增益。

## 创新增益（15）：新增四个可执行能力

| 命令 | 基础 Agent 难以稳定做到的改进 | 边界 |
|-|-|-|
| `preflight --text … --manifest …` | 缺页、扫描空文本/严重乱码、混排、无法解析图表、统计输出缺失误差的机器可识别分流 | 不自行 OCR/PDF 解析；不据文本健康证明科学质量 |
| `coverage result.json` | 五面与六类均有显式审查状态，零问题不再被误判漏查 | 检查记录的真实性仍需 quote/evidence 支撑 |
| `statcheck stats.json` | 可重跑地复核 p-CI、z-p、自由度和样本流，不靠印象 | 不做任意统计模型推荐；特殊区间/单尾/重抽样转人工 |
| `gate result.json` | 原句与证据双哈希、底稿版本、原契约字段、运行版本以及严重度/状态一次总检 | 哈希保证定位串完整，不自动保证语义结论正确 |

正向与破坏性变异都在 `bench/bench_run.py`，未使用正式案例或预制答案。

## 可靠体验（10）

异常表逐项补齐题面六类：稿件缺页、扫描识别失败、图表无法解析、统计输出缺失、语言混杂、材料不足，另列原文不可得。每类规定识别字段、恢复动作、partial/failed 状态和禁止推断，避免失败后空白或伪报“已完成”。合法中英混排、不可读图但正文可读、缺失统计输出但其他材料可读均只降级，不全盘误杀。

## 生态贡献（10）

`SKILL.md` 写清输入输出、五面/六类、异常表、字段算法和调用命令；`templates/checklist.md` 可直接复用；`scripts/review_tool.py` 仅标准库且无网络/个人路径依赖；bench 是可运行的规则单元测试。

## 相对基础 Agent 的边界与未解决差距

- 自动统计检查只覆盖明确提供的结构化数值，不能从任意 PDF 完美恢复表格，也不能证明所提取记录完备。
- coverage/gate 能强制留痕，不等于证明审查者真的读懂全文；最终科学严重性仍需原文与人工方法学复核。
- 尚未在平台固定三案例、三次重复条件下取得新正确性/召回/误报/人工修改量数据；因此不能声称已追上榜首。下一轮必须用平台原始 traces 做同输入对照并补充跨学科、扫描件和图表压力测试。
