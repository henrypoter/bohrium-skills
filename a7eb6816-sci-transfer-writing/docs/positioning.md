# 创新增益：能力、对照与边界

本版已移除与题面不符的“只写 Results & Discussion”流程，聚焦科研成果转化中的证据保留和受众适配。

| 能力 | 基础 Agent 直写的常见缺口 | 本 Skill 的可执行机制 |
|---|---|---|
| 受众画像→文体约束 | 只在提示中写“通俗易懂”，没有验收 | brief 将公众/专家、体裁小节、篇幅、渠道结构化；audit 阻断缺节、超长、未展开缩写和缺白话解释 |
| 证据取舍 | 压缩时删样本、基准、限制或图表 | required 清单逐项 retention；数字/单位回所引 quote；删除仍需 changes 理由 |
| 来源可核验 | 模型给“大概出处”或改写后的伪引文 | evidence 重开实际文件逐字查找 quote，返回 resolved_source 和 actual_lines，并核对声明行/JSON 字段 |
| 术语锁定 | 同义词漂移、缩写未展开 | canonical/aliases/expanded/plain 一表驱动；别名、首次展开、公众解释分别机检 |
| 论断边界 | 相关写因果、初步写定论 | evidence strength 与正文句级词面联合检查；诚实否定/降调写法零误杀夹具 |
| 逐段接稿 | 只有干净稿，原作者无法逐条接受/拒绝 | 每段 before_quote/draft_segment/action/reason/evidence_ids；新增无记录段落会触发 change_coverage |
| 数据冲突与发布边界 | 任选一个值；未发表材料直接公开 | 冲突组必须 human_confirmed chosen；涉密/未发表必须不外传+人工审查，公开还须批准 |
| 增益诚实性 | 自拟数字声称超过基础 Agent | gain 强制同输入哈希/约束/权限/预算；无平台 baseline 只能 pending_platform |

## 相对通用写作工具的实质改进

通用润色只改变语言表面；本流程把“事实能否保留”变成先行证据闸，再把“改写是否漂移”变成句级审计，最后用“每段是否能回原位”闭环。所有能力由 `scripts/transfer_check.py` 三命令独立运行，无模型、网络或第三方包依赖。

## 可复现证据与不能声称的内容

`bench/bench_run.py` 20 项断言覆盖三命令正向零误杀与独立变异必命中；另有 200 段长稿稳定性。确定性 fixture 对照演示“无核查稿→核查修复稿”的错误和人工条目差，但不是平台基础 Agent 成绩，正式质量增益仍须固定 3 案例 A/B。

边界：不判断原始科研结论本身的真伪，不做 OCR/图表像素取数，不自动验证 DOI 真实性，不在无人工确认下换算单位或裁决冲突；词面边界机检不能穷尽所有学科表达，未知写法需人工终审。
