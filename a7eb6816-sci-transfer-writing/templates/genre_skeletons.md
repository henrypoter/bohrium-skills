# 多文体骨架（选择 task 指定的一种，不混套）

所有骨架均以完整成稿为目标；`[S#]` 只留在复核稿，干净稿删除标签但不改其他字符。指定小节名写入 `brief.required_sections`。

## 公众科普文章
1. **核心发现**：一句可理解结论 + 研究对象/样本 + 关键数值与比较基准。
2. **方法如何支持结论**：用白话说明方法与指标，首次展开缩写。
3. **证据与边界**：适用范围、限定条件、不确定/阴性结果；相关不写成因果。
4. **意义**：只写材料支持的潜在意义，推测必须标“可能/有待验证”。

取舍：优先保留结论、样本、指标口径、数值/单位/基准、限制与图表；先删重复背景和文献铺陈，不删证据。

## 项目申报/转化材料
1. **需求与目标**：来自材料的问题与可验证目标，不新增市场规模。
2. **技术方案与创新**：方法要点、与现有材料的差异，术语一致。
3. **已有证据**：样本、实验/验证条件、指标、图表、引用和证据等级。
4. **转化路径与里程碑**：仅把 task/材料给定的计划结构化；未知写待确认。
5. **风险与边界**：技术、数据、样本、合规和未发表/涉密处置。

## 双语摘要
- 两种语言各自成段，但共用同一组 evidence id；关键数字、单位、样本、限定词逐项对齐。
- 缩写按各语言首次出现展开；canonical 可含 `en`/`zh` 两个锁定形式，禁止一语言拔高另一语言降调。
- 若 task 要求逐句对照，用表格“源文/中文/英文/evidence id”。

## 结构化写作/事实底稿转换
按 task 字段输出，不擅自增加论文式章节。每条字段值带 evidence id；无法从材料判断填 `null + uncertainty`，不得用通用知识补齐。数组/表格的行序、图表编号和引用键保持可机读。
