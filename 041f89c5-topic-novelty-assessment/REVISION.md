# 修订说明：科研选题与创新性评估 v2.0.0

本轮保留基础引用与主题检查，按自评缺口补“检索覆盖、证据回链、冲突证据、综合结论”和五类异常处置；没有修改共享核心。

## 新增方法与评分对齐

- **可检验问题**：`question_check` 要求对象、可操作变量、真实基线、预期结局、成功标准和可证伪条件，避免只把研究设想改写成问句。
- **检索覆盖与异常**：`search_check` 核验检索源、检索式、时间窗、hits/returned/screened、选中记录回链与 coverage。接口失败/权限不足必须保留 error、降级状态并进 uncertainty；零命中、文献过少不得推出全局无人研究。
- **创新边界**：`novelty_check` 强制最近邻工作按 task/method/data/evaluation/conclusion 建矩阵，创新差异逐篇回链原文位置与摘录；区分方法、数据、场景迁移和结论修正，场景迁移不得标成方法创新，绝对新颖性字段必须为 false。
- **可行性前提**：`feasibility_check` 覆盖数据、算力、实验、时间、人员；verified 必须有文献或 case.json 的精确来源与 quote，assumption/unknown 必须有理由和验证动作，并检查决策与前提状态一致。
- **冲突与综合结论**：`decision_check` 要求冲突并列至少两篇文献立场、说明对决策影响；研究空白回链比较/创新记录；综合结论回链问题、证据和创新判断，与可行性及“已被覆盖”状态保持一致。
- **可核验版本**：新增 `provenance_check` 重算 case 和每条来源（含排除项）的 SHA-256；`schema` 强制 run 的 skill/tool 版本、输入指纹、生成时间和来源快照。
- **证据回链**：保留 `cite_check` 的漏引/悬空/缺定位检查，比较矩阵、创新差异、冲突立场和可行性证据进一步要求逐字 quote。

## 相对基础 Agent 的边界

基础 Agent 常能分别写“问题、创新、可行”三段，但难以稳定保证它们引用同一研究问题、同一最近邻集合和同一组前提。本 Skill 新增的是跨字段一致性闸：从问题 id 到比较矩阵、创新差异、可行性状态再到最终建议均可机器追踪；检索失败与权限不足也形成结构化记录，而不是静默遗漏。

**仍不能替代**：机检不能证明文献真实存在或引文语义支持，不能证明全领域最新/无人研究，也不能替代真实资源核查和预实验。未实现在线检索器、PDF OCR 或权限绕过，只使用环境已有工具和合法可得材料。开发环境未跑平台基础 Agent 对照，bench 22/22 不是正式案例得分，也不能证明使用增益；gain 未实测必须为 null。
