# 使用增益公平对照报告（确定性路径对照）

复跑：`python3 bench/bench_run.py`（退出码 0 = 全部样例符合 golden 预期；结果自动落 `bench_results.json`）。

## 对照设计

同一批**自拟样例**（`cases/`，非平台正式案例）上，三条路径完成同一适配任务：

| 路径 | 流程 | 模型上下文 |
|-|-|-|
| baseline（无 Skill 基础 Agent 手工流程） | 规范+原稿通读进上下文 → 逐项人工比对规格 → 手工改稿（golden 标注条数）→ 试编译 2 次 → 目检 PDF | 规范全文 + 原稿全文×2（改后重读核对） |
| skill（全功能路径） | `tpl_parse → fit_check(预检) → tpl_fit(幂等改稿+渲染) → fit_check(编译复核)` | 各脚本 stdout 摘要（spec/compliance/fit 明细为 JSON 落盘，按需检索） |
| **lean（SKILL §1 主路径）** | `tpl_fit --guide … --render`（一条命令出成稿）→ `fit_check --compile`（可选校验） | 两条命令的 stdout 摘要 |

lean 路径是 harness 实际要跑的最小路径（**每样例 2 条命令**），它的存在是为了让"调用门槛"可度量：成稿命令自带模板解析，不需要先 parse 再 check 再 fit。

度量与诚实边界（不声称项）：

- 度量**路径开销、可核验性、产物完备性**；**不度量 LLM 端到端改稿质量**（需平台 harness 跑固定案例，本地不可声称）。
- baseline ops 为文档化的保守模型（比对项数+人工改动数+3 次编译/目检），非实测计时；ctx 同样为静态模型（通读+重读）。
- 样例均为自拟 fixtures，仅用于路径对照与方法演示。

## 结果（3 样例聚合，全部 expect 通过）

| 指标 | baseline | skill | 改善 |
|-|-:|-:|-|
| 动作数 ops（合计，全功能路径） | 55 | 11 | **-80.0%** |
| 动作数 ops（合计，**主路径 lean**） | 55 | 6（每样例 2 条） | **-89.1%** |
| 模型上下文字符数（合计，全功能） | 4003 | 1254 | **-68.7%** |
| 模型上下文字符数（合计，lean） | 4003 | 767 | **-80.8%** |
| 机器可判定检查项 | 0 | 35 | +35 |
| 可独立复核产物数 | 3 | 16（lean 17） | +13 |
| 修改留痕条数（before/after/reason） | 0 | 7 | +7 |

逐样例要点：

- **c1_compliant（合规稿）**：pre 11 项全 pass、fit applied=0（几何选项顺序不同但语义相等时零改动）、post 12 pass + 编译 ok + fidelity 干净——「零误伤、可只核不改」。
- **c2_badlayout（坏版式稿）**：pre 7 fail（含左/右边距 1in≠3.0cm 命中，上/下 1in=2.54cm 不误杀）；fit 确定性改稿 7 项 + 渲染 ok；post 12 pass、编译 ok、fidelity 干净；**二次运行 applied=0（幂等）**。
- **c3_pkgconflict（包冲突稿）**：`pkg_conflicts=2`（natbib+biblatex 双引文后端、hyperref 重复）被显式预检并进入 `conflict_precheck`；baseline 无包清单抽取手段，通常只能等编译报错后逐个排查。

## 结论与边界

在本对照度量的维度上，加载 Skill 相比基础手工流程：全功能路径动作数降 80%、主路径（lean）降 89%（每样例 2 条命令即可产出可交付成稿+PDF，第 3 条才校验）、模型上下文体积降 69%~81%、每项规格获得机器判定、产物由「1 份改后稿」扩展为「规范清单+合规核对+编译验证+diff+留痕」共 16 件可复核物。
不声称：答案质量更高（未测）、真实论文版式的全部复杂度（样例为自拟）、docx 深层排版（仍半自动，见 SKILL「限制」）。
