# 公平对照基准报告（bench）

本报告由 `bench/bench_run.py` 生成，数据可复跑：`python3 bench/bench_run.py`（结果同时落 `bench/bench_results.json`）。

## 对照设计

同一批样例文献、同一个阅读任务，在两条路径下完成：

| 路径 | 做法 |
|-|-|
| **baseline**（无 Skill 的基础 Agent 朴素流程） | 整篇读入 → 人肉试关键词定位（失败重试）→ 整段复制成答案 → 手抄笔记 |
| **skill**（加载本 Skill） | `open → search → select → qa → note → export` 一次闭环，锚点自动核验与落盘 |

样例（`bench/cases/`）：`c1_short`（短文 4 行）、`c2_long`（综述体 ~4.5k 字符，关键数据埋在 4.2 节且**引文跨行**）、`c3_scanned`（无文本层图片，检验诚实降级；该图片由脚本运行时在临时目录生成，以保证提交包内只含 UTF-8 文本文件）。
题面与期望引文见 `bench/golden/`。

## 实测结果

| 指标 | baseline | skill | 说明 |
|-|-|-|-|
| 需进入模型上下文的正文（字符，可对照样例合计） | 2298 | **324** | **降 85.9%**；长文单例 2185 → 219（降 90.0%） |
| 手工易错动作数（通读/试错翻找/复制粘贴/手抄笔记/往返核对） | 10 | **0** | 全部转为可复跑 CLI 调用 |
| 答案锚点可机器核验（逐字/归一化） | 0/2 | **2/2** | baseline 无结构化锚点，不可复核 |
| 可独立复核的落盘产物数 | 0 | **6** | 每例 3 件：`reading_record.md` / `annotations.json` / `result_draft.json` |
| 无文本层材料的行为 | 读不出正文，无标注 | **`no_text_layer` 显式降级** | 仍产出 3 件带 `needs_confirmation` 的产物，不编造答案 |

JSON 外壳开销（字段名等）单列：2558 字符，属机器可解析元数据，不占模型推理上下文。

## 三条可复核的结论

1. **效率**：同一任务下，手工易错动作从 10 次降到 0 次；长文只需读入命中的片段与选中段落上下文（219 字符），无需通读 2185 字符。
2. **质量（可核验性）**：baseline 的答案没有任何机器可复核的位置绑定；skill 的每条答案携带 `prefix/exact/suffix` 三段式锚点 + 物理页/行号 + 置信度，可独立复算。
3. **可靠性**：无文本层材料上 skill 显式降级为 `no_text_layer` 并仍交付 3 件带 `needs_confirmation` 的产物，而 baseline 读不出正文也无标注能力。

附：跨行引文（`仍能维持` / `初始活性` 之间被换行切断）在本次迭代中修复为可核验（`normalized` 通道），且能正确回落到原文第 62 行——这是真实 PDF 的常态，此前的实现会误判为「未核验」。

## 边界（不夸大）

- 本对照度量的是**路径开销与锚点可核验性**，**不**度量 LLM 端到端答案质量；后者需要平台 harness 跑固定案例，本报告不声称「答案更准」。
- 锚点核验是对「答案是否真的来自原文」的机械核验，不能替代领域专家对答案科学性的判断。
- 样例为自拟样例文献（非官方评测案例），用于路径对照与方法演示。
